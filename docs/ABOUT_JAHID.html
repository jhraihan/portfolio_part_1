3.1 The four strongest interview answers

Each of these is a genuine engineering problem Jahid solved and can explain unscripted. They are the highest-value material in the entire profile.

Order state machines under an unreliable gateway

MicroMart

Taking a payment is simple in isolation. Keeping order, inventory and payment state consistent is not: users abandon payments mid-flow, gateway callbacks arrive late or twice, and inventory must never be decremented for an unpaid order.

What he concluded
The interesting part of a feature is usually its failure cases. Once the order states and their legal transitions were made explicit, most of the conditional logic scattered through the views simply disappeared.

Authorisation is two questions, not one

EduFlow

Every endpoint must answer both may this user perform this action and on which records. Answering only the first leaves a teacher able to reach another teacher's course by changing an id in the URL.

What he concluded
The interface never decides access. The API scopes every queryset by role; the frontend hides controls purely as a convenience. Roles designed in from the start stay in one place — roles added afterwards become scattered conditionals.

Streaming breaks the request/response shape

IntelliChat

The connection stays open while text arrives in fragments, and a stream can end in more than one way: complete, fail midway, or the client disconnects during generation. He defined an explicit event protocol — meta, repeated delta, then done or error — so the frontend always knows which occurred rather than inferring it from a stream that simply stopped.

What he concluded
Designing the client/server protocol first made both sides straightforward. And persistence changes what an interface can promise: once conversations were stored rather than held in memory, a reload stopped being a data-loss event.

The schema decides what is possible later

MediDesk

Storing a prescription as text would have been quick, but a prescription is genuinely structured: one consultation links to several medicines, each with its own dosage and duration.

What he concluded
Because prescriptions were modelled as real relations, catalogue search and dosage linking came almost for free; a text field would have required a migration and a rewrite. An appointment is likewise a lifecycle, not a row.

An important distinction

Two projects (IntelliChat, PromptCanvas) integrate external model APIs — Google Gemini and Hugging Face. That is software engineering work against an HTTP API: streaming, latency, credential handling, persistence.

It is not a claim of AI/ML expertise, and Jahid asked explicitly that it never be presented as one. There is no AI/ML skills section anywhere — no RAG, embeddings, vector databases, LangChain, agents or fine-tuning. He is at the learning stage and said so; even a "currently learning AI engineering" line was drafted and then removed at his request.

His stated long-term ambition is to become an AI-native software engineer — building systems where modern AI is a first-class part of the architecture rather than an afterthought. That is recorded here as a goal and, on his instruction, appears nowhere on the public site.

Across four independent projects and four independent write-ups, the same conclusion appears in different words each time: get the structure right early, because structure decided late becomes mess everywhere.

  • MicroMart — "once the transitions were explicit, most of the conditional logic disappeared"
  • EduFlow — "roles designed in from the start stay in one place; roles added afterwards become scattered conditionals"
  • MediDesk — "the schema decides what the application can do later"
  • IntelliChat — "designing the client/server protocol first made both sides straightforward"

Four projects converging on one principle, arrived at independently, is a stronger signal than any single claim on a CV. It is worth raising in an interview.

5.3 A second recurring theme

He is consistently drawn to the failure cases rather than the happy path — abandoned payments, duplicate callbacks, streams that die mid-generation, ids changed in the URL, reloads that lose state. That is unusual at this level and is the most senior-reading instinct in the profile.
